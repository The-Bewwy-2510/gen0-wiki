Game data & IDs

The numbers you need when you edit a savegame or game files by hand: the item ID of every weapon, attachment, ammo type, augment, skin, item and material (one ID per quality), and the hashes the save uses for regions, map locations, safehouses, skills, research tasks, challenges and statistics. Everything is generated from the same extracted game data as the rest of the wiki. Click an ID to select it for copying.

Quality IDs

Every quality of a weapon or attachment is a separate item with its own ID, so changing a weapon's quality in a save means swapping its item ID for the ID of the same weapon in the other quality (the Gen0 Editor does exactly that and leaves the record's timestamp, seed and ID alone). The tables below use these quality numbers:

Challenge hashes34 challenges, 132 tiers

Each challenge is a chain of tiers, and the save keeps one entry per tier in Characters[].Challenges: its Id is the Tier id below, and its one child, the tier's objective, holds the progress in CompletionsDone (Objective is the objective's hash in the challenge data). A tier is complete (CompletionState 4) once the progress reaches its target. Progress is the tier's range: it starts where the previous tier ended and is complete at the second number. All tiers of a challenge carry the same progress value, each clamped to its own range, which is how the Gen0 Editor writes it. IDs are signed 32-bit numbers, as in the decoded save. The game only adds a challenge to a character the first time it is played with, and the trees marked DLC need their DLC. What each challenge asks and awards is on the challenges page.

How the data was read

The Gen0 Extractor builds an index of the game's .tab / .arc archives (recovering the file names from their Jenkins hashes) and reads the files straight from the archives: the ADF data files and the in-game text table for items, the location files for positions and IDs, the tuning files for damage and health. The files' own notes say:

  • stats.json: Read from the game's own tuning files (layout .epe files, .ammotunec projectile tuning, .ftunec blast tuning, weapon_tuning.bin and difficulty_settings) using the DECA-Dec-26 extractor, and machine senses from settings/hp_settings/animal_senses.bin.
  • loadouts.json: Read from the game's own entity files (editor/entities/characters/machines/<type>/<layout>.ee) and the English text table, using the DECA-Dec-26 extractor.
  • missions.json: Story and side missions from missions/missions.group.hpmissionsc. Regions come from each briefing's Location line, else the mission's map files. Mission state is read from the save's MissionCampaigns.
  • location_crates.json: Per map location (by save hash): object ids of its loot crate spawn points (CLootCrateSpawnPoint), own file first, nearest first. The save stores them word-swapped (see spawn_point_value).
