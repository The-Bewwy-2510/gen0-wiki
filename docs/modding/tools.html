The Gen0 tools are five small Windows programs for Generation Zero, each in its own folder of the repository. They share one way of working: Run without building.bat starts a tool straight from its Python source, and Build Gen0 <Tool>.bat turns it into a standalone Gen0 <Tool>.exe with PyInstaller. Each one opens a game-styled window with tabs and footer hotkeys like the game's menus.

Running and building

  1. Install Python 3 and tick Add python.exe to PATH. Have Brave or Google Chrome installed.
  2. Download the repository (GitHub: Code → Download ZIP) and unpack it.
  3. In a tool's folder double-click Run without building.bat to try it. The first run installs the Python packages that tool needs.
  4. Optional: double-click Build Gen0 <Tool>.bat for a standalone .exe (a minute or a few). Keep the .exe in its folder: it saves its settings and output there. Rebuild after changing any source file.

Every tool runs a small web server that only your computer can reach (127.0.0.1, a random port and a private access token) and shows its window with its own browser profile, so your normal browser tabs, extensions and history are not touched. Everything a tool creates while running (settings, logs, backups, built mods, exports, built .exe files) is in the repository's .gitignore.

Workflow

  1. BROWSE to your savegame (it starts in the game's Saves folder) and press LOAD. The original is copied to Backup\.
  2. Make your changes; the LOG tab lists every one.
  3. SAVE (Ctrl+S). The editor checks the rebuilt save, writes it through a temporary copy and reads it back before it replaces the original.
  4. Start the game and load the character.

Sharing a mod

Export saves the ticked tabs' choices as mods\<name>.json (a few KB, no game files). The other person puts it in their own mods\ folder, presses Import, picks it and builds. The same game version gives exactly the same mod. Skins aren't part of Export, because they point at PNG files on your PC.

How it works

All edits are same-size and in place: nothing in the game's bundles moves. This is where each tab's change lives:

TabFiles it patches
Machinessettings/hp_settings/reserve_0.bin (each population's target count set to 0) and settings/spawn_defs/spawn_animals_defs.bin (removed machines point at a file that doesn't exist). Friendly ticks, the RC tick, the spy tick and the Companion are never touched.
PlayerCarry weight in gdc\global.gdcc; max health and storage in settings\playersettings.playersettingsc; stamina in player_movement.mtunec inside local_player_character.ee (the whole 50 MB file goes into the mod).
Companioncomp_load01-03.ee, companion.aitunec, companion_armor.bin (in global.gdcc), its ammo and weapon files.
WorldEach loot container's .ee (PersistentTimer, the game's default 14400 s = 4 hours); the 281 loot tables in settings/all_loot_crates.lootcrates. The backpack you drop on death is never changed.
VehiclesEach vehicle colour's .ee (driving physics in .vmodc, lights / horn / invulnerable in the .epe). Top speed raises engine revs and gearing and lowers air drag by the same factor, so the vehicle really reaches it.
SkinsBuilt last, on top of the other tabs: a new item in global.gdcc, a body model and textures packed into every quality of the weapon's .ee, a skin entity, a 128×128 icon, its name, and (when locked) a health station box holding the skins.
From the game files
Stamina is a "heart rate" in the game files: sprinting raises it 25 per second up to 100 (4 seconds of sprint), and it refills at 50 per second after a 2 second pause. Loot qualities q1 to q6 have falling weights in the loot tables.

Using the models in Blender

  • File → Import → glTF 2.0 (.glb). Textures are embedded (World, NPCs and Places use the shared PNGs in textures\ by default: keep models\ and textures\ together, or pick In each model).
  • Pose rigged models in Pose Mode, not Edit Mode.
  • Animations: open the _rigged model and pick an Action in the Action Editor / NLA editor. Walk / run / turn animations include the root motion; additive ones (names ending _add) show on top of the rest pose.
  • A Places export is an empty at the place's centre with the models below it: set its location to 0 to bring it to the origin.

Gen0 VR

Installs or uninstalls the SteamVR mod (the F1 console with VR) in the game folder, with a backup of what was there, and switches VR on or off.

Changes

Game
Steam version only

VR MOD tab

  • Shows what is in the game folder now and what is ready to install.
  • Turn VR on + mode: true stereo (default), alternate eye or flat screen. Written to GZVR.txt when installing; once the mod is in, a change is saved right away (the game reads the file every second, even while it runs).
  • INSTALL copies the DLLs from mod\ into the game folder. Use the VR game settings also copies settings_vr.json over the game's settings.json (the replaced one goes to backup\).
  • UNINSTALL leaves one of these in the game folder: what was there before the first install, the console without VR, or no console at all. Everything else the mod left goes too (openvr_api.dll, nvngx_dlss.dll, GZVR.txt, GZTerrainExperiment.ini, GZWatch.txt, old .ini backups, crash dumps in logs\); files you may have made are moved to backup\. GZConsoleThingy.ini and the console's logs\ stay.

The GAME tab picks the Generation Zero folder (Browse, or Find looks in your Steam libraries). Install and uninstall wait until the game is closed.

Playing in VR

  1. Install with Turn VR on ticked.
  2. Start SteamVR, then the game.
  3. In the game options turn Motion Blur off.
  4. F1 → Extra tab → VR: 3D on/off, recenter, eye distance. F7 recenters. A Detail Level (LOD) of about 6 looks right.

After a game update, uninstall if the game crashes at start. More on the VR mode on the console page.

Building the mod

Build VR mod.bat builds mod-source\ twice with Visual Studio Build Tools 2022 (C++) and CMake: with VR into mod-build → mod\, and without VR (GZ_VR=OFF) into console-build → console\. It doesn't copy anything into the game folder: install with Gen0 VR.
