Modding Generation Zero

Generation Zero can be modded in three ways: files the game loads from a dropzone folder instead of its own archives, a DLL next to the game's exe that adds an in-game menu, and editing the savegame. This tab covers all three and the free Gen0 tools that do the work for you, plus a reference of the item IDs and hashes you need when you edit files by hand.

The Windows tools in gen0-tools all look alike: a small Python program that opens a game-styled window (a local web page shown by Brave in app mode, or Chrome when Brave isn't installed; never Edge) with its own private browser profile. Nothing is uploaded anywhere. The Gen0 Hub starts them from one window. The game folder is only ever read, except by Gen0 VR, which installs the VR mod's files there.

Dropzone mods and launch options

The game normally reads everything from the packed archives in archives_win64. With the launch options below it also reads a folder called dropzone next to GenerationZero_F.exe, and a file in there with the same path as a game file is used instead of the original. Mods made by the Gen0 Modder and the Gen0 Map Editor are such files.

Turning dropzone on (Steam)

  1. In your Steam Library, right-click Generation Zero and choose Properties.
  2. Paste this into Launch options:
    --vfs-fs dropzone --vfs-archive archives_win64/initial --vfs-archive archives_win64/supplemental --vfs-archive archives_win64/optional
  3. Create a folder called dropzone next to GenerationZero_F.exe if it isn't there yet.

Without these options the game ignores dropzone, so a mod that "does nothing" is usually a missing launch option. Leaving the options in with an empty dropzone folder plays the normal game.

Installing, removing and updating a mod

  • Install: the Modder builds its mod into a dropzone\ folder next to itself. Copy everything inside it into the game's dropzone folder. The Map Editor's Install button copies its build in for you.
  • Turn a mod off: delete the files it added from the game's dropzone (or put another mod's copies of those files back).
  • After a game update: take the mod out before playing, then build it again from the updated game files. A mod is a patched copy of the game's own files, so an old one can undo or break what the update changed.
Why mods clash
The game reads its settings from gdc\global.gdcc, a bundle holding byte-exact copies of the settings files. Loose settings files in dropzone are ignored, so every Modder mod is a patched global.gdcc; two mods that both change it can't simply be copied over each other. The Modder can build on top of another mod's dropzone folder instead (its GAME tab).

DLL mods: the F1 console

The console is a file called xinput9_1_0.dll that goes next to GenerationZero_F.exe. Windows loads it with the game, and it adds an in-game menu you open with F1. It changes the running game's memory, not its files, so it needs no launch options and can be used alongside dropzone mods. See the console page for every feature, and Gen0 VR for installing it with a backup.

On Linux / Steam Deck (Proton) add this to the launch options so the game uses the mod's DLL instead of the built-in one:

WINEDLLOVERRIDES="xinput9_1_0.dll=n,b" %command%

If you also use dropzone mods, put the --vfs-fs ... options after %command%.

Save editing

The Gen0 Editor opens a savegame, shows it in game-styled tabs and writes the result back over the original. Before anything is written it runs a set of save checks, writes through a temporary copy and reads the file back to compare it. When a save is loaded, the file as it was is copied to Backup\savegame-backup next to the editor.

Saves are in Documents\Avalanche Studios\GenerationZero\Saves\ (or under OneDrive\Documents when Windows moves your Documents there). Newer saves are zstd-compressed; the editor reads both those and the older uncompressed ones. EXPORT JSON writes the decoded save as readable JSON to Output\savegame.json.

Item IDs, location and skill hashes for editing a save by hand are on the game data page.

Where things are

The game folder path is the Steam default; the tools have a Browse button, and Gen0 VR, the Extractor, the Modder and the Map Editor also find the game in your other Steam libraries (another drive, e.g. D:\Steam). The Map Editor asks for the folder with archives_win64 in it when it can't find one.

Backups and safety

Heads up
Back up your save before using the editor or playing with a mod. Copy the whole Saves folder somewhere safe; it takes seconds.

Each tool also keeps its own backup, next to the tool unless noted:

ToolBackupWhat it holds
Gen0 EditorBackup\savegame-backupThe save exactly as it was loaded
Gen0 Modderbackup\<date>\The previous build, moved there before each new one
Gen0 VRbackup\before-install\What was in the game folder before the first install (renamed with the date when an uninstall uses it, never deleted), plus replaced settings.json files
Gen0 Map Editor%LOCALAPPDATA%\Gen0 Map EditorBackups made when it installs into the game

Things that can go wrong

  • Weapon skin mods change the save. Once you have used a skin from a Modder skin mod, removing the mod's files breaks that save. Keep the mod installed for that save, or restore a backup from before the skin.
  • Game updates. Remove dropzone mods before playing after an update and rebuild them. If the game crashes at start after an update with the console installed, uninstall it (Gen0 VR).
  • The console changes game memory and may cause instability or crashes. Its new features use addresses of the Steam build; on the Microsoft Store build they stay off.
  • Machines already alive stay. Removing a machine type with the Modder stops the world refilling it; machines that already exist in your save remain until destroyed.
  • Unsigned programs. Windows may warn the first time you start a built .exe, because it isn't signed: choose More info, then Run anyway.
  • Close the game first. Gen0 VR waits for the game to close before installing or uninstalling, and a console build can't copy its DLL into the game folder while the game runs.
  • Co-op. Some console features (spawning machines, controlling or making a machine invulnerable) only work for the host or for machines your game hosts.
