# Writing a section of the Gen0 Wiki

The wiki is generated by `python build/build.py` from the JSON in `build/data/` into `docs/` (GitHub Pages).
Each tab of the site is made by Python modules in `build/sections/`. A module has:

```python
from wiki.site import esc, slug, norm, fmt, pct, table, infobox, bar, note, cards, kv, minimap, qbadge, tag, REGIONS, QUALITY

def collect(site):   # register every page/anchor you make, so other sections can link to it
    site.register("weapon", "N9 Handgun", "weapons/n9-handgun.html", "N9 Handgun",
                  icon="img/items/weapons/wpn_handgun_us_03_alpha.png", desc="US handgun, 9mm ...",
                  aliases=["wpn_handgun_us_03", "N9"], keywords="pistol handgun 9mm")

def build(site):     # write the pages
    site.page("weapons/n9-handgun.html", "N9 Handgun", body_html, "weapons", sub="weapons",
              crumbs=[("All weapons", "~/weapons/index.html")], desc="...", infobox_html=infobox(...),
              kind="Weapon · Handgun", lead="<p>...</p>")
```

Read `build/wiki/site.py` (helpers, `Site.page`, `Site.register`, `Site.link`, NAV) and `build/static/wiki.css` /
`wiki.js` (classes and widgets) before writing. Build only your module with `python build/build.py <module>`; it
prints your page count, links to unregistered targets, missing images and broken links. Everything must build
with **no broken links and no exceptions**.

## Rules

- **Links**: every internal URL starts with `~/` (site root) – `site.page()` rewrites them to relative links.
  Link to other sections with `site.link(kind, key)` / `site.url(kind, key)`, never by hard-coding their paths:
  a missing target then shows as plain text instead of a broken link. Anchors you register (`path#id`) must exist
  as an element `id` on your page.
- **Images**: use `site.img("img/...")` (returns "" when the file is missing). Icons live in `docs/img/`
  (`augments crowns currencies items keys locations schematics skills skins stock vanity`, copied from the
  Gen0 Editor). Paths in the data like `assets/stock/x.png` become `img/stock/x.png`; map glyphs and icons
  `map/glyphs/x.png` / `map/icons/x.png` are at `map/map/glyphs/x.png` / `map/map/icons/x.png`.
- **Only write files you own**: your module(s) in `build/sections/`, and if you need extra CSS a file
  `build/static/<module>.css` that you load with `head_extra='<link rel="stylesheet" href="~/assets/<module>.css">'`.
  Don't edit `wiki/site.py`, `wiki.css`, `wiki.js`, `build.py` or other modules – if you need a framework change,
  say so in your final report.
- **Accuracy first.** Numbers come from `build/data/` (read straight from the game files). Never invent stats,
  locations or drop rates. General game knowledge you are sure of (how a mechanic works) is welcome as prose; say
  "the game files show ..." when quoting data. If the data has a caveat (a `note`, `_about`, `reading_the_numbers`),
  pass it on to the reader. Where the current game files contradict something widely repeated in older guides /
  the old fan wiki that you are confident about, add a `note(..., "fix")` callout ("Older guides say X; the current
  game files have Y"). Don't attribute claims to other sites unless you are sure of them.
- **More detail than the fandom wiki**: tables of every value the data has (per quality, per ammo, per layout, per
  difficulty), internal names (`<code>`), cross-links (weapon ↔ ammo ↔ attachments ↔ augments ↔ skins; machine ↔
  machine weapons ↔ detection; mission ↔ region ↔ locations; schematic ↔ item ↔ materials), a short
  explanation of how to read each table, and practical tips derived from the numbers.
- **Style**: plain, friendly English; sentence case in text, the bars/titles are upper-cased by CSS. Use
  `bar(title)` for each h2 section (they build the table of contents), `table()` for data (sortable),
  `infobox()` for the right-hand summary of an entity page, `cards()` for index grids, `note()` for callouts,
  `minimap(x, z, label)` for a location (world coordinates as in markers.json / map_locations.json).
  A big list gets a filter: `<div class="filterbar" data-for="TABLE_OR_LIST_ID"><input placeholder="Filter..."><button class="chip on" data-g="type" data-f="*">All</button><button class="chip" data-g="type" data-f="main">Main</button><span class="count"></span></div>`
  then rows `<tr data-f="main archipelago">` (wrap `table()` output in `<div id="...">` or give list items
  `class="fitem" data-f="..."`). In-page tabs: `<div class="tabset"><div class="tsbtns"><button>Q1</button>...</div><div class="tspane">...</div>...</div>`.
- **DLC & unreleased**: tag DLC content with `tag("FNIX Rising", "dlc")` etc. Content the data marks as
  unreleased / `dlc03` gets `tag("Unreleased", "unreleased")` and a short note that it is in the files but not in
  the game.
- Pages must work at phone width (tables scroll sideways inside `.tablewrap`; don't set fixed widths).

## Who owns what (kinds you register → where they live)

| module | pages | kinds it registers (key = …) |
|---|---|---|
| `home` | `index.html basics.html dlc.html about.html` | `dlc` (DLC name / pack hash) |
| `weapons` | `weapons/index.html`, `weapons/<slug>.html`, `weapons/quality.html`, `weapons/skins.html` | `weapon` (name as in stats.json `player_weapons`; aliases: names in IDs.json / augments.json / vanity skin subs, internal `wpn_*` names), `skin` |
| `ammo` | `weapons/ammo.html`, `weapons/attachments.html` | `ammo` (ammo name as in stats/stock, alias internal name), `caliber` (stock.json `sub`, e.g. `9mm`, `.44`), `attachment` (IDs.json name) |
| `augments` | `weapons/augments.html`, `weapons/augments/<slug>.html` | `augment` (name, e.g. `Acidic`; alias research slug) |
| `machines` | `machines/index.html`, `machines/<slug>.html`, `machines/detection.html` | `machine` (type: `Tank`, `Harvester`, `Hunter`, `Tick`, `Seeker`, `Runner`, `Firebird`, `Lynx`, `Wolf`, `Reaper`, `Vulture`, …; also `Tank (Prototype)`-style names as anchors) |
| `machine_weapons` | `machines/weapons.html`, `machines/difficulty.html`, `machines/rivals.html` | `machine-weapon` (colloquial name in stats.json `machine_weapons`) |
| `world` | `world/index.html`, `world/<region>.html`, `world/locations.html`, `world/locations/<slug>.html`, `world/safehouses.html`, `world/control-points.html` | `region` (key `archipelago` …, alias display name), `location` (name; alias hash as string), `safehouse`, `controlpoint` |
| `collectibles` | `world/collectibles.html`, `world/collectibles/<type>.html`, `world/keys.html` | `collectible-type` (markers.json sub key, alias name), `key` (keys.json name) |
| `missions` | `missions/index.html`, `missions/<slug>.html`, `missions/challenges.html` | `mission` (name; alias id), `challenge` |
| `items` | `items/index.html`, `items/materials.html`, `items/schematics.html`, `items/companion.html` | `item` (stock.json name; alias raw), `material`, `schematic` (name; alias hash) |
| `character` | `character/skills.html`, `character/apparel.html`, `character/vanity.html`, `character/packs.html` | `skill`, `apparel`, `vanity`, `pack` (pack hash as string) |
| `modding` | `modding/*.html` | `tool` |

## Data files (build/data)

| file | what |
|---|---|
| `stats.json` | Machine & Weapon Stats: `player_weapons` (per category → weapon → ammo damage, armour/component multipliers, falloff, quality multipliers, experimental overrides), `machine_health` (faction → class → type → layout → components), `machine_detection`, `machine_weapons`, `difficulty`, `_about.reading_the_numbers` |
| `loadouts.json` | Machine Loadouts: every machine layout with its weapons, in-game names, internal names, deployment notes |
| `gamedata.json` | skills, schematic currencies, research (augment research tasks), regions, threat levels, rival levels, rival titles, stats, challenges, safehouses, locations (with ids, kinds, regions) |
| `augments.json` | which augment fits which weapon (`fits`: [weapon index, bitmask of qualities]) |
| `schematics.json` | schematic trees and all 229 schematics (cost, recipe, prerequisites, icon) |
| `stock.json` | every inventory item: ammo, items, materials (name, internal name, group, stack size, icon) |
| `missions.json` | 145 missions with region, pack, summary, description, steps (`opt` = optional) |
| `keys.json` | bunker barcodes, keycards, door keys, mission items |
| `vanity.json` | apparel, face paint, weapon skins, emotes, vehicles, companion cosmetics; `packs` = pack hash → item names |
| `IDs.json` | weapons per category with item ids per quality, attachments with weapon compatibility (`WPNCompat` = weapon `ToolID`s), ammo ids, skins, augment ids |
| `icons.json` | item id → icon path |
| `markers.json` | map markers: collectibles, schematics, house photos, safehouses, control points, beacons; region borders |
| `map_locations.json` | every map location with kind, region, x/z |
| `loot.json` | placed loot (weapons by quality, attachments, items, materials, crates) with positions |
| `location_crates.json` | loot crate spawn points per location (by location hash) |
| `kinds.json` | object kinds used by the map editor |
